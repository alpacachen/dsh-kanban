# 工作流使用指南

打开侧边栏「看板·工作流」，在顶部工作区右侧切换 **Kanban / Workflow**。Workflow 首页用两级列表展示流程及其任务：箭头展开或收起子任务与创建任务入口，点击流程名称打开流程详情，点击任务打开任务详情。

## 创建和修改流程

点击 **对话创建流程**，在新聊天中描述目标、输入、AI 步骤、交付结果和人工审核点。Agent 使用 `workflow_create` 创建完整流程，或先通过 `workflow_list` 读取当前 revision，再调用 `workflow_update` 保存修改。Host 自动继承发起聊天的模型与推理配置；Agent 不接收模型设置字段，也不需要查询或询问模型。后续模型调整由用户在流程详情中完成。AI 修改保留已有阶段的用户模型设置，新增 AI 阶段继承当前编辑聊天的配置。

保存后就能创建任务，没有草稿、发布、启用或停用步骤。页面提供流程图；点击阶段打开 DSH 原生弹窗，可直接编辑执行要求或审核文本，点击保存或按 ⌘/Ctrl+Enter 提交。AI 阶段复用 DSH 输入框的 ModelSelect 组件切换模型和原生推理档位，点选立即保存，也可恢复使用 DSH 默认模型；切换模型不会丢失正在编辑的文本。模型目录复用 DSH 的 `session/modelCatalog`，不修改聊天或全局模型设置。阶段名称、类型、顺序及新增、删除仍通过聊天让 Agent 修改；人工节点没有模型配置。编辑流程只影响新任务，已有任务保留执行时的流程快照。

## 首页与详情

- 首页流程行展示展开箭头、黑白图标、名称与任务数，创建任务入口作为最后一个子项放在任务列表末尾，随流程一起折叠。任务行用输入内容作为主文字，过长时省略，悬停或聚焦预览内容，点击查看全文，同时展示执行状态、当前步骤和更新时间。
- 首页直接展示表格，不设搜索和筛选；最后一行居中提供对话创建流程入口，空列表也使用同一入口。
- 流程详情展示说明与流程图，阶段要求和模型配置通过点击节点在弹窗中查看，不放任务列表和创建按钮。任务详情始终展示紧凑流程图，高亮当前阶段；点击节点在 DSH 原生居中弹窗查看该阶段的原生会话、成果或审核内容，不使用 Tab。通过面包屑返回流程或首页。
- 页面使用一个纵向滚动区域，内容自然延伸到底部。流程图使用 React Flow 自由画布，默认按 100% 展示；任务详情初始定位当前执行阶段，不显示内部滚动条。拖动或触控板双指滑动平移，鼠标滚轮、捏合或 ⌘/Ctrl 配合滚轮缩放，点击「查看全图」才缩放到完整流程。窗口尺寸及任务状态更新不重置用户的画布视角。

## 执行任务

在首页对应流程行点击 **创建任务**，直接在行内输入任务内容并发送，也可用 ⌘/Ctrl+Enter 提交。不填任务名称，不选择模型，不打开创建弹窗。阶段使用项目内该 Task 独有的产物目录作为默认工作目录，原项目绝对路径随任务传给 Agent，加载 DSH 默认 Agent 预设，工具和授权沿用 DSH。

任务详情展示流程图和产物列表，点击节点打开 DSH 原生居中弹窗查看该阶段的详情与结果，复用 DSH 原生聊天视图查看思考、工具和回复。弹窗固定查看所点阶段，流程推进时不会跳转会话，当前执行节点仍独立高亮。人工审核节点在弹窗中展示绑定成果和审核操作。弹窗按内容和窗口尺寸适配，成果使用 DSH 原生 Markdown 排版，长文本在内容区滚动；Esc 或关闭按钮返回流程图；关闭不会取消任务。

弹窗工作过程使用原生聊天滚动区域，页面其他详情继续自然滚动，不叠加过程记录列表。输入框不在任务页显示，DSH 原生工具授权组件保留；需要进入完整聊天时仍可点击 **打开执行会话**。查看过程不会重新下发阶段任务。

Workflow 不额外设置联网／文件／命令权限、工具次数、模型轮数、阶段总时长或输出 token 预算；Ultra 和子 Agent 是否可用由模型与 DSH 配置决定。

## 人工审核与异常处理

流程含人工节点时，任务会停在该节点等待用户决定：

- **通过并继续**：接受当前保存的报告并继续。
- **打回重做**：填写意见，回到流程规定的 AI 步骤；保留历史报告。
- **重试**：已停止的失败任务重新执行当前阶段。
- **终止任务**：打开小确认弹窗后请求 DSH 停止；当前执行阶段会话标题也提供入口。“终止中”仍在等待停止确认。

DSH 重启或插件重载后，中断执行会保留为“需要处理”，不会自动重跑。点击 **核对旧执行**，先核对旧命令及外部操作已经停止，再勾选确认；强退宿主后，macOS 上的命令可能继续运行，新进程的作业清单为空并不代表旧操作已退出。Workflow 同时核对原生会话所有权、关联作业与原始输入身份；会话或作业仍工作时不能释放执行位置。核对不会向会话发送消息或取消后来追加的聊天。核对后，已请求终止的任务进入“已终止”，其他中断任务仍由用户选择重试当前阶段，上游已提交阶段不重跑。终止中的旧执行也可重新核对。

已完成审核节点仍可查看决定时间及该次绑定的报告。任务界面显示当前审核状态，生成文档只保留内容与生成时点，不因批准而自动改写已审核文件。

人工审核不提供 Agent 自动批准入口。报告缺失、断线或审核轮次变化时不能批准。文件修改不会因打回或终止自动回滚。

删除入口位于流程或任务详情，使用小弹窗二次确认。首页行内不放删除按钮；尚未停止的执行不能删除或盲目重派。

当前适配 DSH **0.2.2-rc.3**。后端变更需重载插件，前端刷新不足以替换执行模块。旧 SQLite 数据和历史快照保留，不迁移或覆盖看板数据。

## 阶段交接与产物位置

每个 AI 阶段／重试使用独立的 DSH 会话。阶段输入由本阶段要求、任务原始输入、所有仍有效的上游阶段交接摘要、产物索引和人工反馈组成；不再自动携带上游成果全文，也不会直接继承上一阶段的完整聊天历史或工具调用。

阶段在完成本轮结果后，需在最终回复末尾附加 `workflow-handoff` Markdown 代码围栏，围栏中包含 `<workflow-handoff>` JSON：`conclusions`（每条含结论 text 与依据 evidence）、`openIssues`（缺口、分歧与不确定性）、`nextActions`（后续需读取、核查或执行的事项）。摘要目标为 300–600 中文字符／150–300 英文单词，最多接收 2400 个 JSON 字符；数字、单位、日期、标识与依据位置需明确。详细论证仍放在完整回复和产物文件中，不把之前报告全文再复制一遍。摘要由当前阶段在同一次执行中生成，不额外调用模型。Workflow 阅读界面隐藏保留围栏和内部编排输入；旧回复默认展示阶段报告，可展开原始会话。原始字节和 hash 保留，不改写持久化记录。

调度器保留每个有效阶段自己的摘要，不反复改写成一份累积总结。交接同时包含完整报告相对路径、SHA-256、文件大小与当前 Task 的文件索引。后续阶段需按需读取重要结论的依据；没有摘要、摘要格式错误或过长时，`needsRead: true` 要求先读该报告全文，不截断或猜测关键结论，也不会仅因摘要格式问题让任务失败。被审核打回替代的旧摘要不再进入有效上下文；文件索引仍可能出现旧文件，存在并不代表结论有效。

阶段最终回复保存为一个不可变文本附件，文件名为 `workflow-<attemptId>.txt`。Workflow 在当前 Profile 的 `workflow-poc/workflow.sqlite` 中按任务、阶段访问和执行尝试记录附件引用与 SHA-256。DSH 本地附件服务保存字节：`<DSH_HOME>/attachments/v1/files/<hash前两位>/<hash>/workflow-<attemptId>.txt`，底层内容对象位于 `file-objects/<hash前两位>/<hash>`。调度器核验有效附件内容后提取摘要；完整内容通过任务目录中的 `.workflow-results/<attemptId>.md` 按需读取。这些副本属于只读执行历史，不列入可删除的交付文件；副本缺失或被修改时，从已核验附件修复，不影响后续阶段。审核打回后旧成果仍留作历史，但从有效上游输入中排除。

每个 Task 的产物目录为 `<项目>/.dsh/workflow-artifacts/<taskId>/`。创建时建立目录；同一 Task 的各阶段、重试和返工共用它，不同 Task 使用不同目录。阶段以此为默认工作目录，生成文件默认落到这里；原项目路径仍可用于读取资料和按需求修改代码，工具与授权不变。每次成功阶段的最终回复也保存到 `.workflow-results/<attemptId>.md`，不同执行尝试不会覆盖彼此。历史任务已有的项目文件不猜测归属、不自动搬迁。

任务详情的产物列表递归显示该目录中的文件并自动刷新，跳过符号链接；文件接口校验路径归属，不能跨 Task 取文件。点击文件在当前任务中打开 DSH 原生 Modal，Markdown 与代码使用 DSH 的 MarkdownText / CodeBlock，图片、音视频、PDF 使用浏览器能力，读取复用 DSH 已认证的 `/api/file`。预览不切换会话。弹窗仅提供文件预览，其他格式可从产物目录查看。目录仍可通过 DSH 原生路径能力打开。文件大小限制沿用 DSH 文件读取接口，不新增 Workflow 限额。

## 删除产物与历史优化

每个产物行可删除单个文件，操作前弹窗二次确认。删除校验文件仍属于该 Task 且版本与确认时一致；文件被执行阶段更新时需先刷新再确认。不会递归删除目录，也不会删除数据库中的执行、审核记录或 DSH 不可变成果附件。

删除任务时，确认弹窗会提示同时永久删除该任务产物目录及其中的所有文件（包含各阶段回复副本）。正在执行或尚未确认停止的任务需先终止，才能删除。只清理该 Task 的独立目录，不触及项目其他文件、其他 Task 的目录或符号链接指向的文件。删除意图先提交到数据库并停止调度，再异步清理目录；清理失败会提示后台继续处理，重启后也会恢复清理。数据库提交失败不会提前删除文件。执行、审核记录与 DSH 不可变成果附件仍保留。

在流程详情点击「根据历史优化」会打开新聊天并填入预置分析要求，不自动执行任务。Agent 用 `workflow_list_tasks` 读取此流程的历史摘要，按 workflowVersionId / versionNumber 区分版本，再用 `workflow_get_task` 读取代表性任务的旧阶段、结果索引、错误和审核意见。需要完整报告时显式传入 `includeOutputText: true`，阶段对话通过 `workflow_get_stage_trace` 按需读取。保存优化只影响未来新建任务；正在运行、等待审核或已经结束的任务继续使用原快照，旧阶段 ID、产物目录和记录均不迁移。

需要速度分析时，`workflow_get_stage_trace` 只读该 Task 指定阶段／执行尝试的持久化会话日志：用户与 AI 消息、记录下来的思考文本、工具参数与结果、阶段总耗时、模型轮次与首输出等待、token/cache 数据、重试、压缩和授权事件。对话按 fromSeq / limit 分页，概览覆盖整次执行；后续在同一会话追加的无关聊天不会混入阶段记录。它不恢复或重新运行 Agent，也不返回连接配置与传输请求头。

工具耗时是 tool/call 到 tool/result 的墙钟间隔，可能包含排队、授权或等待子任务。observedToolWallMs 合并重叠区间，不能把并行调用耗时简单相加；模型耗时从 step/start 计算，可能包含准备与重试等待。没有 token、时间或日志的数据保持未知；服务端内部排队、工具内部子步骤、独立子 Agent 的内部聊天不能仅凭阶段主会话自动得出。执行中日志可能尚未刷新到持久化存储。

## 执行收尾与刷新

Workflow 不设置阶段回复大小或组合输入长度的执行上限，模型和上下文能力沿用 DSH。阶段已经执行完成后，附件、报告副本或数据库暂时无法保存时，只重试保存，不重新调用模型；核对入口可处理原生会话已空闲但数据库尚未收尾的任务。无法确认执行已停止时仍需读取 DSH 的会话所有权和工作状态，避免重复执行。

任务状态接口默认只返回报告索引。阶段弹窗打开后才读取报告正文，历史报告按需展开；交付文件区不混入阶段报告与旧尝试。活动任务轮询文件索引，任务结束后仅在进入页面、阶段状态变化或手动刷新时更新。列表连接短暂失败后会自动重新连接。折叠流程时，父行仍显示进行中和待处理的任务数量。

## 数据与备份

同时备份当前 Profile 的 `workflow-poc/workflow.sqlite`、DSH 附件存储，以及各项目的 `.dsh/workflow-artifacts/` 目录。停用插件后备份，或使用 SQLite 一致性备份；不要直接复制运行中的数据库而遗漏 WAL。保留 `workflow-poc` 历史目录名是为了继续读取已有记录，不做无必要迁移。

看板数据独立保存，见[看板备份说明](guide.zh.md#数据与备份)。任务目录删除后，Workflow 不提供恢复功能。

界面控件、内置错误和日期跟随 DSH 的中文／英文设置；用户命名、阶段要求、反馈与产物保持原文。[English guide](workflow-guide.en.md)。
