# Workflow 实现与验证状态

Workflow 是 Kanban 内的模式，沿用工作区切换、主题和原有面板边距。首页以流程和子任务组成二级列表，流程详情只展示定义、阶段要求与模型；任务详情始终展示流程图，高亮当前阶段，点击节点通过 DSH Modal 查看该阶段的原生会话、成果和审核。

## 模型与执行

AI 阶段的 `modelSelection` 保存 provider、model 和可选 reasoningEffort。Agent 创建新阶段时继承当前聊天的真实模型配置，创建与修改工具不提供模型参数；后续用户在流程阶段弹窗中复用 DSH ModelSelect 调整模型与推理档位。模型不是任务选项，创建任务只提交流程版本与输入内容。

runner 按任务所绑定的流程版本选择各阶段模型，Attempt 快照记录实际选择。流程修改、全局默认模型变化和人工返工不会改写已有任务版本。未指定模型的旧阶段沿用创建任务时保存的 DSH 默认配置；旧 SQLite 数据和配置不迁移。旧 API 的任务名称与模型字段仍可被解析，但新的任务模型由流程阶段决定。

执行采用项目目录、DSH 默认 Agent 预设、原生工具与授权。Workflow 负责调度、成果核验、人工审核、返工和终止，不另设工具权限或模型轮数、工具次数、阶段总时长、输出 token 预算。成果仍校验持久化 Session、请求对应关系、正常结束和附件 hash；未确认停止的旧执行不会自动重派。

## 界面

创建任务入口是流程下最后一个子项，随流程一起折叠；展开行内输入框即可发送，也支持 ⌘/Ctrl+Enter；没有任务名称或模型字段。输入内容在列表、标题和面包屑中省略显示，列表和标题支持 Tooltip。流程详情没有任务列表或创建按钮，也没有草稿、发布、启停能力。

任务详情不使用 Tab。选中的 AI 阶段通过原生 SessionReference、`conversation.content` 与聊天视图展示模型公开的推理摘要、工具和回复；阶段说明、成果及历史记录与原生会话共用滚动区域。弹窗固定查看所点阶段，不随执行推进切换会话；当前执行节点仍独立高亮。查看不会重新下发任务，关闭释放本地会话引用、恢复节点焦点。阶段使用 DSH Modal，窄屏全屏，Esc 关闭。人工审核节点展示绑定成果和审核控件；反馈、断线、成果缺失、轮次更新与不可用返工目标的保护均保留。

删除仍位于详情页，用小弹窗二次确认。常规界面回归使用隔离数据；真实任务执行须在用户明确授权的测试范围内进行。

重启测试的上游阶段只执行一次，第二阶段保留中断尝试并新增一次成功尝试；有效报告两份，均通过原附件 hash 和交接格式校验。`checkpoint.md` 的 SHA-256 在强退、重启、重试及终审后始终为 `a559a7d2afc1e226a8cdd2070796b7444ac76b13b686d38ba79005bad1872ce3`。新交付文件保留 75% 完成率、未知预算、未上线事实与上游依据，没有“待审／未获批准”等随审核状态过期的标签；通过审核没有改写该文件。

实际测试发现并修复：

1. **编排协议泄漏到阅读界面。** 新回复把交接 JSON 放入保留的 `workflow-handoff` 代码围栏，通过 DSH 官方围栏 HOC 在 Workflow 会话中隐藏；生成的阶段输入通过官方 userText 展示扩展还原为任务输入与反馈。旧无围栏回复默认显示清理后的阶段报告，仍可展开原始会话。持久化记录、核验字节及 hash 均不变。
2. **批准后文件仍写“待审”。** 修正创建／修改预置 prompt、阶段执行说明和测试流程定义，由界面管理实时审核状态。流程定义升级保留旧 Task 快照，不批量改写已审核历史产物。
3. **网络错误误报成日志完整性错误。** 按已关联的 DSH turn/end 原因区分连接失败、模型错误、中断和不完整输出；无法核验日志时仍保持未知。实际第二次断流已显示 `WORKFLOW_NETWORK_FAILED`，原生重试策略不变。
4. **原生确认框阻塞测试与页面。** 终止操作改用现有小 Dialog，并在当前执行阶段标题提供入口；取消、确认及嵌套阶段弹窗交互均验证。正常用户取消不再污染 runner 全局错误。
5. **冷启动 Session 所有权不能证明旧命令退出。** SIGKILL 测试实际观察到 macOS 子命令存活，而新 Host 的进程内 jobs 清单为空。恢复后端拒绝无确认的冷启动未知执行核对，界面要求核对旧命令／外部操作已停止再确认；仍在运行的原生会话或作业即使勾选也不能释放。未确认请求不改变任务 revision 或尝试数量。

已完成审核节点保留决定时间及当次绑定的报告，避免审核结束后无报告可看或误用后续成果。断网页面保留原列表并提示当前为上次读取的数据，不能提交执行或审核；网络恢复后提示自动消失。1280px、820px、390px 页面检查均无横向溢出，390px 确认弹窗宽 280px；实际表格字体为 Host 系统字体、13px。

未赶上注入时机的两次先导任务不计入故障通过证据；它们分别完成或终止，记录保留。最终隔离 runner 无运行、无保存收尾、无清理积压、无全局错误，也没有遗留活动作业。

### 发布判断与边界

在 macOS、DSH `0.2.2-rc.3` 的已验证范围内，自动执行、人工打回与批准、产物隔离、断网重试、执行中终止及强退后的人工恢复通过，插件稳定版发布准备检查通过。这里的重启恢复指“保留中断状态，经人工核对后恢复”，不承诺强杀宿主会自动停止所有命令或撤销外部副作用。已有旧文件按原版本保留，人工审核只批准绑定报告，不表示项目目录文件的不可变快照。

尚未进行 Windows／Linux 真机验收，也未以本轮短流程证明任意长任务或所有外部系统的恢复行为。当前内核自身是 rc 版本；插件验收不代表内核获得稳定版保证。故障验收阶段未发布 npm；随后整理为 1.12.0 的功能 PR，合并与发布状态以 GitHub 和 npm 为准。

现有桌面 DSH 已通过插件管理关闭／启用 Kanban 完成重载，没有退出应用。核对运行中模块已包含新的断网分类、operatorConfirmedStopped 校验及参数转交；原有两个验收任务仍为 completed，runner 空闲且无错误。桌面 GUI 确认完成审核节点展示决定时间及当次绑定报告，旧任务仍使用 v1 快照。Host 变更仍需重载插件，单纯刷新前端不足以替换已加载的 Host 模块。
